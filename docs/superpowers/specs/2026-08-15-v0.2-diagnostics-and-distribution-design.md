# dsh-request-flight-recorder v0.2 Diagnostics and Distribution Design

**Status:** Approved in conversation; written specification pending final review  
**Date:** 2026-08-15  
**Target version:** 0.2.0  
**Target runtime:** published DeepSeek Harness 0.1.0-rc.6 packages  
**Repository:** `https://github.com/abinzhao/dsh-request-flight-recorder`  
**Primary owner and check path:** abinzhao; local `pnpm check`, packed-consumer smoke test, and official CLI profile smoke test

## Decision Summary

Build v0.2 as one installable bundle with two internal boundaries:

1. The existing recorder core owns capture, correlation, bounded retention, query, health, and diff.
2. A human-command consumer registers `/flight` only while the official `commands` service is available.

Publish prebuilt output through npm and commit the deterministic `lib/` output for commit-pinned GitHub installation. Do not add a `prepare` script. GitHub and npm publication remain separate, explicitly authorized release actions after implementation and review.

## Decision Question

How should the plugin become directly useful and officially installable without changing model requests, forcing optional UI dependencies, persisting request content, or making source installation execute an untrusted build script?

## Context and Forces

| Force | Rationale |
|---|---|
| Human usability | The current service is queryable only by another in-process plugin; ordinary users cannot inspect records. |
| Observation transparency | The plugin must not add model tools, prompts, messages, or request mutations. |
| Privacy | Structural records deliberately omit model-visible content; command output must preserve that boundary. |
| Profile compatibility | Official profiles include commands, but custom minimal profiles may not. Core capture must still activate there. |
| Official installation | RC6 installs external bundles through `dsh plugin --profile <name> add <spec>` and activates only packages declaring `dsh.bundle.patch`. |
| GitHub installation safety | Git source contains no registry-built output. Without committed output it needs `prepare`, and pnpm requires explicit `allowBuilds`. |
| Community discovery | Public repositories carrying the `dsh-plugin` Topic appear under `https://github.com/topics/dsh-plugin`; there is no central submission registry. |
| RC churn | Pre-release contracts can change. Supported versions must remain exact until tested. |

## Goals

- Add process-instance health counters with explicit semantics.
- Extend retained-record queries without breaking the existing `list()` API.
- Add deterministic, content-free differences between retained records.
- Add a session-isolated `/flight` human command through the official command registry.
- Support npm, commit-pinned GitHub, local checkout, and tarball installation through the official bundle mechanism.
- Provide clear English and Chinese documentation, community metadata, contribution guidance, and release history.
- Preserve 100% statement, branch, function, and line coverage for production TypeScript.

## Non-Goals

- No persistence, database, RPC, Web UI, client module, or export file.
- No model-visible Tool, Skill, Prompt Section, Context Provider, or message injection.
- No raw prompt, message, tool argument, tool result, variable value, or stable content fingerprint.
- No semantic diagnosis, anomaly scoring, recommendations, or billing-grade usage accounting.
- No broad peer-version range before compatibility checks pass.
- No repository creation, push, npm publication, release, or Topic mutation during implementation.

## Alternatives

| Option | Decision | Reason |
|---|---|---|
| One package with optional command consumer | **Selected** | One install, core works without commands, and command lifecycle remains independently disposable. |
| One package requiring commands | Rejected | A minimal custom profile without commands would leave the recorder pending or fail startup. |
| Separate core and command packages | Rejected for v0.2 | Adds installation, Bundle, version, and documentation complexity before independent release cadence is needed. |
| Persist records before adding diagnostics | Rejected | Freezes an immature data contract and introduces retention, migration, and privacy obligations. |
| Add a model Tool instead of a human command | Rejected | Changes model-visible context and violates the observer-only product boundary. |
| GitHub source installation with `prepare` | Rejected | Requires users to authorize install-time code execution outside the Agent sandbox. |
| npm-only distribution | Rejected | Removes the community's normal commit-pinned GitHub installation path. |

## Consequences

### Positive

- Existing service consumers remain compatible.
- Users gain direct diagnostics without giving the model another tool.
- Minimal profiles retain the recorder core without a command dependency.
- npm and GitHub installations both use prebuilt output.
- Query, diff, and health become reusable foundations for future UI and persistence consumers.

### Negative

- Generated `lib/` output becomes repository-reviewed content.
- A command result is written by the official command runtime into the Session Log.
- Core and command behavior share one release even though their runtime dependencies differ.
- Health counters are process-local and reset after HMR or restart.

## Reversibility

This is a two-way decision. The command consumer can later move to a separate package because it depends only on the public recorder service. Reconsider splitting when either:

- the command consumer needs an independent release cadence, or
- another surface requires the core package but cannot tolerate shipping command code.

Removing committed output is also reversible after npm becomes the only supported source or the official Git installer gains a safe prebuilt-artifact path.

## System Map

```text
Official system-prompt/assemble
            |
Official agent/request
            |
Official llm/stream + Agent initiator
            v
    Capture and Correlation
            |
    Content-free Projection
            |
      Bounded Ring Store
       /       |       \
    Query    Health     Diff
       \       |       /
        Recorder Service
              |
     optional ctx.commands
              |
          /flight
```

### Data Flow

1. Capture observes authoritative official events.
2. Correlation requires the exact Signal, Agent identity, and Session identity.
3. Projection creates whitelisted structural summaries.
4. Retention inserts immutable records and reports any eviction to health accounting.
5. Terminal stream observations update retained records and process-instance counters.
6. Query and diff read immutable retained records.
7. The optional command consumer restricts record access to the invoking Agent's Session and formats bounded plain text.

### Trust Boundaries

- All plugins run in one trusted Node.js process. This plugin is not a security boundary.
- Public service methods trust typed same-process callers and validate only configuration-like values such as query limits.
- Command input is untrusted human text and must be parsed, bounded, and converted into typed service calls.
- Command output contains no request content but is persisted in the invoking Session's command lifecycle.

## Bounded Context Map

| Context | Responsibility and model | Upstream | Downstream | Relationship and translation |
|---|---|---|---|---|
| Capture | Official request events and exact runtime identity | DSH event contracts | Projection, Health | Conformist to official contracts; converts runtime objects into owned observations. |
| Projection | Content-free request and assembly summaries | Capture | Retention, Diff | Anti-corruption layer; whitelists fields and drops content. |
| Retention | Immutable bounded `FlightRecord` collection | Projection | Query, Diff, Command | Shared kernel for recorder-owned read models. |
| Diagnostics | Query, Health, and typed Diff contracts | Capture, Retention | Command and future consumers | Customer/supplier; exposes stable owned types, not Cordis internals. |
| Command | Session-isolated parser and text formatter | Diagnostics, official Commands | Human UI adapters, Session Log | Conformist to official command result contract; translates typed diagnostics to bounded text. |
| Distribution | Manifest, Bundle patch, built artifacts, docs | Source/build | DSH profile, npm, GitHub | Anti-corruption layer between source package and installation mechanisms. |

## Interaction Style

- Capture remains synchronous local projection around an existing stream; it adds no network or storage hop.
- Query, health, and diff are synchronous request/response over process memory.
- The command is an optional human request/response interaction.
- No polling or push API is introduced. Capacity is 128 by default and v0.2 has one human consumer; subscription is deferred until a live UI requires it.
- Stream observations remain incremental, but only terminal state is published to retained records in v0.2.

## Public Contracts

### Query

Extend the existing query without changing its call shape:

```ts
export interface FlightRecordQuery {
  readonly sessionId?: SessionId
  readonly turn?: number
  readonly step?: number
  readonly provider?: string
  readonly model?: string
  readonly outcome?: FlightOutcome['kind']
  readonly limit?: number
}
```

Rules:

- `list()` remains newest-first and returns a frozen detached array.
- Every supplied filter is conjunctive.
- `limit` must be a positive safe integer.
- Omitting `limit` returns every retained match.
- Query never reads evicted records.

### Health

```ts
export interface FlightRecorderHealth {
  readonly captured: number
  readonly completed: number
  readonly active: number
  readonly retained: number
  readonly evicted: number
  readonly correlationMisses: number
  readonly projectionFailures: number
}
```

Counter semantics:

- `captured` increments after a record is successfully inserted.
- `completed` increments once when a captured request first reaches any terminal outcome, even if its record was evicted.
- `active` is the number of captured attempts without an observed terminal outcome.
- `retained` is the current Ring Store size.
- `evicted` increments when insertion removes the oldest record.
- `correlationMisses` increments only for a marked Agent Loop request that lacks a usable Signal or fails pending-request, Agent, or Session correlation.
- Unmarked direct LLM requests do not affect health.
- `projectionFailures` increments whenever assembly or request projection fails and capture continues fail-open.
- Every `health()` result is a fresh frozen snapshot.
- All counters reset with the plugin instance.

The store changes `insert(record)` to return the evicted record or `undefined`, and exposes read-only `size`. Active attempt identity is tracked independently from retention so terminal settlement remains correct after eviction.

### Diff

```ts
export type FlightScalarValue = string | number | null

export interface FlightValueChange {
  readonly kind: 'value'
  readonly field: FlightScalarField
  readonly before: FlightScalarValue
  readonly after: FlightScalarValue
}

export interface FlightCounterChange {
  readonly kind: 'counter'
  readonly field: FlightCounterField
  readonly key: string | null
  readonly before: number | null
  readonly after: number | null
  readonly delta: number | null
}

export interface FlightNamedChange {
  readonly kind: 'named'
  readonly field: FlightNamedField
  readonly name: string
  readonly change: 'added' | 'removed' | 'changed'
  readonly beforeSize: number | null
  readonly afterSize: number | null
}

export type FlightChange =
  | FlightValueChange
  | FlightCounterChange
  | FlightNamedChange

export interface FlightRecordDiff {
  readonly fromId: RequestAttemptId
  readonly toId: RequestAttemptId
  readonly changed: boolean
  readonly changes: readonly FlightChange[]
}

export type FlightDiffResult =
  | { readonly kind: 'ok'; readonly diff: FlightRecordDiff }
  | { readonly kind: 'missing'; readonly ids: readonly RequestAttemptId[] }
```

Diff fields cover:

- Provider, model, reasoning effort, temperature, max tokens, and terminal outcome kind.
- System characters, message total, role/source/block counters.
- Tool names and parameter-node changes.
- Prompt Section and Context character changes, plus variable-name membership.
- TTFT, total time, input tokens, and output tokens when present.

Rules:

- Missing optional values are represented by `null`.
- `delta` exists only when both numeric sides exist; otherwise it is `null`.
- Named contributions are compared by official unique contribution name.
- Changes use deterministic field and key ordering.
- Equal records produce `changed: false` and an empty frozen list.
- A missing retained id returns the typed `missing` result and never throws.
- The diff contains no model-visible content.

## Human Command

Register one global command when `commands` becomes available:

```text
/flight
/flight latest
/flight show <request-id-prefix>
/flight diff
/flight diff <from-prefix> <to-prefix>
/flight health
```

Command metadata:

- Name: `flight`
- Description: `Inspect content-free model request diagnostics`
- Input hint: `[latest|show <id>|diff [from] [to]|health]`
- `recordInput: false`

Behavior:

- Empty input and `latest` render the current Session's newest retained record.
- `show` resolves a unique id prefix only among the current Session's retained records.
- Argument-free `diff` compares the current Session's two newest retained records, oldest to newest.
- Explicit `diff` resolves both prefixes only inside the current Session.
- Ambiguous, missing, malformed, or cross-session identifiers return a stable command error.
- `health` shows process-global aggregate counts but no other Session identifiers or records.
- Command output is English in v0.2 and plain text without ANSI control sequences.
- Command output is limited to 4,096 UTF-16 code units. Truncation appends a stable marker and never splits a surrogate pair.
- The official command runtime records result text in the invoking Session Log; documentation states this explicitly.

Optional registration uses Cordis injection lifecycle. Absence or later removal of `commands` removes only the command consumer and does not dispose or pause recorder core.

## Runtime Dependency Decisions

| Dependency | Adoption criteria | Failure behavior | Debug/change/fallback/exit |
|---|---|---|---|
| Official Agent, LLM, System Prompt services | Exact rc.6 types and tested events | Core remains pending if required service is absent | `--dump-config`, integration tests, exact peers; update only after compatibility matrix passes |
| Official Commands service | Optional and lifecycle-owned | No `/flight`; core remains active | Command discovery list and lifecycle tests; can split consumer package later |
| Process memory | Default capacity 128; no persistence promise | Oldest record evicted; active settlement accounting continues | `health()`, configurable capacity; restart clears all state |
| Committed build output | Deterministic from source | CI fails on drift | Rebuild through `pnpm build`; remove after npm-only distribution becomes acceptable |

## Bundle and Official Installation

The package remains an installable Bundle:

```json
{
  "dsh": {
    "bundle": {
      "patch": "./cordis.patch.yml"
    }
  }
}
```

The patch inserts one recorder row with `capacity: 128`. Users can override the entire row through their later profile or home patch.

Documented installation commands:

```sh
# npm
dsh plugin --profile web add dsh-request-flight-recorder

# commit-pinned GitHub source with committed output
dsh plugin --profile web add "github:abinzhao/dsh-request-flight-recorder#<commit-sha>"

# local checkout
dsh plugin --profile web add .

# tarball
dsh plugin --profile web add ./dsh-request-flight-recorder-0.2.0.tgz
```

Verification:

```sh
dsh --profile web --dump-config
dsh --profile web
```

Removal:

```sh
dsh plugin --profile web remove dsh-request-flight-recorder
```

- Remove `lib/` from `.gitignore`.
- Commit `lib/index.mjs`, `lib/index.d.mts`, `lib/invariant.mjs`, and `lib/invariant.d.mts`.

- Package import must have no hidden source-checkout dependency.
- Peer dependencies remain exact `0.1.0-rc.6` for DSH packages.

## CI and Verification

Add one GitHub Actions workflow on Node.js 22:

1. Install pnpm from `packageManager`.
2. Install with frozen lockfile.
3. Run `pnpm test:coverage`.
4. Run `pnpm typecheck`.
5. Run `pnpm build`.
6. Fail when committed `lib/` differs.
7. Run `pnpm exec publint`.
8. Run `pnpm pack`.
9. Install the tarball into a fresh consumer and load it in a real Cordis context.

Local release verification additionally installs the tarball into an isolated `DSH_HOME` through the official local RC6 CLI, checks `--dump-config`, and boots only far enough to prove the Bundle row resolves. It must not write to the user's ordinary `~/.dsh`.

## Testing Strategy

All production TypeScript remains under 100% statement, branch, function, and line thresholds.

### Core Tests

- Every query filter independently and in combination.
- Limit validation, ordering, frozen results, and no mutation.
- Every health counter transition.
- Running eviction followed by terminal settlement.
- Direct LLM calls do not count as misses.
- Missing Signal, pending request, Agent mismatch, and Session mismatch do count.
- Projection failures increment and remain fail-open.

### Diff Tests

- Equal records.
- Every scalar field.
- Added, removed, and changed counters.
- Added, removed, and resized tools, sections, contexts, and variables.
- Missing metrics and one-sided numeric values.
- Deterministic ordering.
- One or both ids missing.
- Frozen output and absence of secret fixture content.

### Command Tests

- Optional registration and removal with commands lifecycle.
- No command service leaves core active.
- Every syntax form.
- Empty state, one-record diff, missing prefix, and ambiguous prefix.
- Session isolation for show and diff.
- Health exposes aggregate counts only.
- Output length and surrogate-safe truncation.
- `recordInput: false`.
- Command registration and result text contain no model-visible request content.

### Distribution Tests

- Manifest points to an included parseable Bundle patch.
- Patch mounts the correct package and default config.
- Packed file allowlist.
- Packed consumer import and Cordis load.
- Committed build output drift.
- English and Chinese READMEs contain identical installation commands.

## Decision Table

| Situation | Default | Exception |
|---|---|---|
| Commands service absent | Keep core active, expose no command | None in v0.2 |
| Request cannot correlate | Increment miss and skip record | Unmarked direct calls do not count |
| Diff id is not retained | Return typed `missing` | Never read persistence because none exists |
| GitHub source install | Use committed output, no install script | Reconsider only with a safe official artifact mechanism |
| Documentation language | English canonical plus complete Chinese translation | Command output remains English in v0.2 |
| Record capacity reached | Evict oldest record | Active terminal accounting continues independently |
