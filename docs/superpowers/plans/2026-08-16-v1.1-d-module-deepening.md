# v1.1 D: Recorder Module Deepening Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Move recorder transactions and Harness-specific capture knowledge into deep internal Modules while preserving every public v1 contract and observable behavior.

**Architecture:** A new `FlightRecorderState` owns bounded records, health, revision, active IDs, and subscriptions as one transaction boundary. `registerHarnessAdapter` owns all DSH events, correlation maps, projections, attempt numbering, timing, IDs, and stream observation. The public service becomes a lifecycle composition root, and `/flight` consumes exactly one atomic Reader Snapshot per execution.

**Tech Stack:** Node.js 22.19/24, TypeScript 6, ESM, Cordis 4.0.1, DeepSeek Harness 0.1.0-rc.6, Vitest 4.

---

Execute only after the A plan is green. This plan changes no public runtime
exports, Reader signatures, protocol version, schema version, package version,
record fields, or command grammar.

```ts
  protocolVersion: FLIGHT_RECORDER_PROTOCOL_VERSION,
  recordSchemaVersion: FLIGHT_RECORD_SCHEMA_VERSION,
  capabilities: ['diff', 'health', 'query', 'snapshot', 'subscribe'],

export class FlightRecorderState implements FlightRecorderReader {

  private readonly subscriptions: FlightSubscriptions
  private readonly activeIds = new Set<RequestAttemptId>()
  private captured = 0
  private completed = 0
  private evicted = 0
  private truncatedRecords = 0
  private correlationMisses = 0
  private correlationMissesByReason = emptyCorrelationMissesByReason()
  private projectionFailures = 0
  private subscriberFailures = 0
  private revision = 0
  private disposed = false

  constructor(
    capacity: number,

    this.subscriptions = new FlightSubscriptions(() => {

    })
```

- [x] **Step 4: Implement capture as one transaction**

Add:

```ts
capture(record: FlightRecord): void {
  if (this.disposed) return
  if (record.outcome.kind !== 'running') {
    throw new Error('captured record must be running')
  }
  const evicted = this.store.insert(record)
  this.captured += 1
  this.activeIds.add(record.id)
  if (evicted !== undefined) this.evicted += 1
  if (hasFlightRecordOmissions(record.omissions)) this.truncatedRecords += 1
  this.change()
}
```

Insertion, omission accounting, active registration, and simultaneous eviction
must call `change()` exactly once.

- [x] **Step 3: Implement transaction methods**

Add:

```ts
settle(id: RequestAttemptId, outcome: FlightOutcome): boolean {
  if (this.disposed || !this.activeIds.delete(id)) return false
  this.completed += 1
  this.store.update(id, record => ({ ...record, outcome }))
  this.change()
  return true
}

correlationMiss(reason: CorrelationMissReason): void {
  if (this.disposed) return
  this.correlationMisses += 1
  this.correlationMissesByReason[reason] += 1
  this.change()
}

projectionFailed(): void {
  if (this.disposed) return
  this.projectionFailures += 1
  this.change()
}

dispose(): void {
  if (this.disposed) return
  this.disposed = true
  this.store.clear()
  this.activeIds.clear()
  this.subscriptions.clear()
  this.resetCounters()
}
```

`settle()` increments `completed` even when an active record was evicted; the
store update remains a no-op. `change()` saturates revision and publishes the
saturated value.

On synchronous downstream throw, settle with finite classification and rethrow

```ts
if (
  observation.kind === 'finished'
  && (
    observation.finish.kind === 'aborted'
    || observation.finish.kind === 'error'
  )

  state.settle(id, {
    kind: 'threw',
    error: { kind: 'error' },
    ...(observation.firstChunkMs === undefined
      ? {}
      : { firstChunkMs: observation.firstChunkMs }),
    totalMs: observation.totalMs,
    ...(observation.usage === undefined ? {} : { usage: observation.usage }),
  })
} else if (observation.kind === 'threw') {

    ...observation,
    error: classifyFlightError(observation.error),

  observation.kind === 'finished'
  || observation.kind === 'incomplete'

}
```

Finish Chunk is never replaced, copied, or suppressed.
