# v1.1 B: Multilingual Diagnostics Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add immediate Chinese/English `/flight` output, first-browser-language synchronization, filtered lists, deterministic explanations, and retained-window statistics without changing the v1 record protocol.

**Architecture:** Host locale resolution reads DSH's registered `locale.preference` for every command and selects one complete typed dictionary. A minimal Web Client Half persists DSH's provisional browser locale only when no explicit preference exists. Pure diagnostics functions filter and aggregate one Session-scoped atomic Snapshot; renderers localize their results and retain the 4 KiB bound.

**Tech Stack:** Node.js 22.19/24, TypeScript 6, Cordis 4.0.1, DSH Settings/Locale/Client Runtime 0.1.0-rc.6, Vitest 4, tsdown, Playwright Chromium for the final browser integration gate.

---

Execute after both A and D are green. This plan produces the final 1.1.0
package. It adds no record fields, Reader capabilities, network export,
diagnostics UI, model call, or persistence for flight records.

Implement:

```ts
export async function synchronizeInitialLocale(
  scope: SettingsScope<LocaleSettings>,
  active: ClientFlightLocale,
): Promise<'written' | 'preserved' | 'unavailable'> {
  const before = scope.getSnapshot()
  if (
    before.status !== 'ready'
    || before.mode !== 'host'
    || !before.writable
  ) return 'unavailable'
  if (hasOwnPreference(before.user)) return 'preserved'

  await scope.set(CLIENT_LOCALE_FIELD, active)
  const after = scope.getSnapshot()
  const accepted = readPreference(after.user)
  if (accepted === active) return 'written'
  if (accepted !== undefined) return 'preserved'
  return 'unavailable'
}
```

`hasOwnPreference()` must check own-property presence on a plain object; an
explicit `zh` equal to a base default is still explicit.

- [ ] **Step 5: Implement the Client plugin lifecycle**

Create `src/client/index.ts`:

```ts
export const inject = ['locale', 'settingsScope', 'connection', 'remote']

export function apply(ctx: ClientContext): void {
  const scope = ctx.settingsScope.bind<LocaleSettings>({
    namespace: CLIENT_LOCALE_NAMESPACE,
  })
  let attempted = false
  let running = false

  const sync = async (): Promise<void> => {
    if (attempted || running) return
    const snapshot = scope.getSnapshot()
    if (snapshot.status === 'loading') return
    running = true
    attempted = true
    try {
      await synchronizeInitialLocale(
        scope,
        normalizeClientLocale(ctx.locale.getSnapshot().active),
      )
    } finally {
      running = false
    }
  }

  ctx.effect(() => scope.subscribe(() => { void sync() }))
  void sync()
}
```

Client normalization maps only `en` to English and all other values to Chinese.
`src/client/**` must not import `src/locale.ts`; that Host module imports
Settings contracts that are forbidden in the browser bundle.
The plugin registers no Slot, component, Session listener, command, or flight
record access.

- [ ] **Step 3: Implement three isolated browser cases**

The script accepts one packed tarball, reuses A's supported DSH version, and
runs three independent temporary homes:

1. browser `en-US`, no preference -> Host stores `en`;
2. browser `zh-CN`, no preference -> Host stores `zh`;
3. browser `en-US`, pre-seeded explicit `zh` -> Host remains `zh`.

For each case:

- install the tarball with public `pnpm dlx @deepseek-ai/dsh@<version>`;
- start Web on an ephemeral port;
- launch Chromium with `newContext({ locale })`;
- open the startup URL and require no page error;
- wait until `$DSH_HOME/settings.yaml` contains the expected
  `locale.preference`;
- reload and require the value remains stable;
- close browser/context;
- terminate DSH with `SIGTERM` and require exit code 0;
- remove only that temporary home.

Never print the settings document; print only case names and pass/fail status.
